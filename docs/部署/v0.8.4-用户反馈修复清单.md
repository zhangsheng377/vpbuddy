## 待修复 (按用户编号)

### 1. 会议产物初始刷 vpbuddy demo 内容
**问题**: 新会议一开始 6 个文档块就显示内容 (demo 块尤其烦), 还没说话就有内容看起来很怪
**根因**: 6 docs 模板不限空 state 强制输出"骨架", batch_docs.md prompt 写 "state 无变化 + 首次创建" 仍要求 write_file
**修复**:
- `prompts/batch_docs.md`: 改 "空 state (所有 facts 全空) → 跳过该文档, 不 write_file"; "state 累积无变化 → 跳过 5 docs 整批 (不调 agent)"
- `sub_sessions/batch_docs.py`: 加 `state_empty` 判定, 空直接返回 `{"triggered": False, "skip": "empty state"}`
- 客户端 `vpbuddy-client/ui/index.html`: 6 docs 块初始 placeholder 改"暂无产物; 说话 / 上传文本后自动生成", 收到 SSE 后才显示内容
**验证**: 建新空会议 → 6 块都显示 placeholder → 不收任何 SSE → 30 分钟后仍 placeholder

### 2. 5 个文档格式极繁琐 (200-1900 字节 boilerplate)
**问题**: req/arch/tasks/api/risk 输出大量"YAGNI 不主动建章节""state facts 全空""变化对比表"等空话, 实际信息 1 行
**根因**: prompt 鼓励"即使无变化也 write_file 占位文案"
**修复**:
- `prompts/batch_docs.md`: 精简指令 "内容 <300 字; 空章节用一句 '暂未产出' 占位即可; 不要列'无变化判断逻辑'"
- LLM 输出示范加 "差输出" 例子
**验证**: 拉一段 transcript → 看 req.md 不超过 500 字节, 不含 >300 字节的"判断逻辑"段

### 3. 协作疑问没显示 → 推到了 chat
**问题**: agent 主动消息 ("需要继续选 demo 吗?" "需要我开始 demo 制作吗?") 显示在 chat 框而不是"🤝 协作疑问"面板
**根因**: `agent_proactive.py._run_async` 推 SSE `chat-message` + 标 `is_proactive=True`, UI `renderChatMessage` 当 chat 显示; 真正 collab panel (`panel-collab` SSE `collab-update`) 不收这个
**修复**:
- `agent_proactive.py.trigger()`: 5 trigger (docs_complete/risk_threshold/demo_new_version/silence/time_node) → 推 SSE `collab-update` (`action: "ask"`, `asker: "VPBuddy-agent"`, 推到对应 section: req/arch/tasks/api/risk/demo/docs)
- UI `main.js`: chat 中 `is_proactive=True` → 不再当 user-q 可回答, 改成 "💡 提示" 标签 (灰色); 真问题才显示 "🤝 待答"
**验证**: 触发 docs_complete → chat 不再出现 "需要我开始 demo 制作吗?" 这类问句; 协作疑问面板展开 + 显示

### 4. chat 上传图片 + 说话, 服务端无反应
**问题**: 客户端 `sendChat()` multipart POST `/api/meetings/{id}/chat`, 服务端没响应
**根因**: GPU server 跑老 commit (无 `handle_chat_upload` 路由) 或 chat 路由 path 不对
**修复**:
- GPU pull `3a9eacc` 后用 `handle_chat_upload` 路径要核
- `ui_server.py`: 验证 `/api/meetings/{id}/chat` POST 路由注册
- `kb_api.handle_chat_upload`: 验证 body parse (`text` + `files`) 正确返 200/400
- 客户端: `sendChat()` 失败时显 `e.message` (不是吞错)
**验证**: `curl -F text=hi -F files=@x.png http://gpu/api/meetings/test/chat` 返 200

### 5. demo 版本列表延迟 + 选择不跳转
**问题**: demo 版本下来得很晚 + 选了老版本 iframe 不更新
**根因**: `loadDemoVersions` 异步拉 → 选中老版本时 `loadDemoVersion(v)` 没拿 cache, 重新拉 + 推 SSE 又跳到最新
**修复**:
- `main.js`: 选中老版本 → 立刻 fetch 文件内容 URL 直塞 iframe `src` (不走 SSE)
- 选前最新版 → 维持现状
**验证**: demo_v3 v4 v5 几个版本可选, iframe 跟 select 实时同步

### 6. KB 没上传按钮 + 搜索出 5 个 undefined
**问题**: `kb_search` 返 5 条 `undefined` 显示
**根因**: `kb-results` 渲染走 `r.distance.toFixed(3)` + `r.snippet.slice(0, 200)`, 但 `rag.query()` 返回结构跟 render 不匹配 (字段名不同 / 缺字段)
**修复**:
- `vpbuddy-client/ui/index.html`: KB 面板加上传 `<input type=file>` + `<button>上传入 KB</button>`
- `main.js`: render 兼容 `r.score` 替代 `r.distance`, 兼容 `r.text` 替代 `r.snippet`; undefined 字段降级
- `kb_api.handle_kb_upload`: 上传后推到当前 meeting_id, 不允许 meeting_id 空
**验证**: `kb_search` 返 5 条, UI 显示正常 distance + snippet, 不再 undefined; 上传按钮可上传 .txt/.md/.pdf

### 7. Windows 内录 (WASAPI loopback) 没录到
**问题**: audio_source=loopback/both, 客户端 cpal WASAPI 不暴露 loopback, 退化为 mic
**根因**: cpal 0.15.3 不支持 Windows WASAPI loopback, v0.9.x 计划
**修复**:
- `vpbuddy-client/ui/main.js`: 当 `kind=loopback` + 没有 loopback 设备 → UI 显示 banner "未检测到 loopback, Windows v0.9.x 支持 (当前用 mic 兜底)"
- `vpbuddy-client/ui/index.html`: 加 `<div id="loopback-warning" class="banner-warn" hidden>` placeholder
- `vpbuddy-client/src-tauri/src/audio.rs` (未来): 加 `is_loopback_supported()` + UI 区分显示
**验证**: Windows 测试 (V 自己在 PC 上跑) → banner 显示 + 当前仍能录音 (mic fallback)
