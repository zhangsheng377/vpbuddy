## 〇、口径校准(v1.20, 2026-06-24)

本架构只服务于一个场景: **我(VP/创业者/产品经理)日常跟各种人开会时,需要能把讨论内容实时沉淀为 6 类结构化物(需求/架构/任务/API/风险/Demo HTML)。沉淀物可以跟同龄人协作讨论,也可以作为下一个会议的上下文。**

### 不是:
- ❌ 不是通用 AI agent 框架
- ❌ 不是会议录播/回放/编解码系统
- ❌ 不是客服聊天机器人
- ❌ 不是企业内部知识管理系统(但聊天上传可充当)
- ❌ **不是展示项目 / POC / demo** — 是真生产工具,所有代码/架构/部署按生产级质量做

### 用户故事一句话:
> "我开会时开着 VPBuddy 客户端自动收声,会议结束马上就有 6 类文档+1 个 HTML 原型 Demo,我还能跟 AI agent 对话追问细节、调整方向。"

## 二、session 架构(v1.41, ADR-0041: fork 模型取代独立 session)

**当前架构 (ADR-0041, 2026-07-04):**

```
master session: meeting:{mid}:vp-chat     ← 客户端 chat 页签
   ├── fork → meeting:{mid}:batch         ← 继承 chat 历史, 生成 5 文档
   └── fork → meeting:{mid}:demo          ← 继承 chat 历史, 生成 demo
```

关键设计:
1. **fork = parent_session_id**: 子 agent 从 master session 读取整个对话历史作为初始化上下文
2. **单向继承**: 子 agent 不修改 parent 历史, parent 感知不到 child
3. **LLM provider 统一**: chat 和 doc agent 都走 MiniMax-M3, 确保 fork 上下文兼容
4. **prompt 差异化保留**: system prompt 不同 (chat=对话风格, batch_docs=结构化写作, demo=HTML 生成), parent_session_id 只继承对话历史不覆盖 system prompt

**历史背景:**
- v1.40 及之前 (ADR-0029): 3 个完全独立的 session — chat/reports/demo, 彼此不可见
- v1.41 (ADR-0041): 合并为 fork 模型, chat 上下文自动注入 doc 生成

## 三、文档类型

| 文档 | 生成方式 | 内容风格 |
|------|----------|----------|
| req.md | batch_docs (1 次 LLM 调用 5 文档) | 需求分析, bullet points |
| arch.md | batch_docs | 架构方案, 或占位"暂无架构讨论" |
| tasks.md | batch_docs | 任务拆分, 负责人 |
| api.md | batch_docs | 接口定义, 或占位"暂无接口讨论" |
| risk.md | batch_docs | 风险评估, RISK-XXXXXX 唯一编号 |
| demo HTML | demo agent (独立) | HTML 原型, 可交互 |

所有文档生成通过 **MiniMax-M3** LLM (OpenAI 兼容 API, `https://api.minimax.chat/v1`)。

## 四、数据流

用户的 30 秒讲话经过的完整生命周期:

```
语音输入 (客户端麦克风)
  → 20-30s batch WAV (HTTP POST)
  → funasr paraformer-zh ASR (GPU, ~28s)
  → MeetingState ingest (转写 + 事实抽取)
  → SSE 推流回客户端 (实时文字)
  → controller --once 触发
     → batch_docs agent (fork 自 chat session)
        → AIAgent.chat(prompt + 5 文档路径)
        → MiniMax-M3 LLM 调用 (4-6 次 API call)
        → write_file × 5 (req/arch/tasks/api/risk)
     → demo agent (fork 自 chat session)
        → AIAgent.chat(prompt)
        → write_file demo HTML
  → SSE doc-update 事件
  → 客户端 6 文档面板更新
```

## 五、LLM provider 策略 (ADR-0040 补充)

- 配置位置: GPU 上 `/root/.hermes/auth.json` credential_pool 只保留 minimax
- 环境变量: `/tmp/_vpbuddy_env` (server 启动前 source)

## 七、后台任务队列 (task_manager)

**设计文档**: [ADR-0042](../decisions/0042-task-manager.md)

### 问题

长会议每 30s 产生一个 WAV chunk, 每次 chunk 处理完成后触发文档生成。如果没有 per-meeting 去重, 线程无限堆积, 旧 generation 可能覆盖新结果。

### 方案

引入 `MeetingTaskQueue` (per-meeting 单任务队列) + `DocTaskManager` (全局管理器)。

```
                     ┌──────────────────┐
                     │  DocTaskManager   │
                     │  global singleton │
                     └────────┬─────────┘
                              │
              ┌───────────────┼───────────────┐
              │               │               │
     ┌────────▼──────┐ ┌─────▼───────┐ ┌─────▼───────┐
     │ meeting_a     │ │ meeting_b   │ │ meeting_c   │
     │ MeetingTaskQ  │ │ MeetingTaskQ│ │ MeetingTaskQ│
     │ gen_id: 5     │ │ gen_id: 3   │ │ gen_id: 1   │
     │ current: doc  │ │ current: -  │ │ current: -  │
     └───────────────┘ └─────────────┘ └─────────────┘
```

### 关键设计

1. **debounce**: 新 task 提交时自动 cancel 旧 pending/running task
2. **generation_id**: 递增 ID, 回调检查是否 stale, 防旧写覆盖
3. **global ThreadPoolExecutor**: `max_workers=4`, 所有会议共享
4. **状态**: QUEUED → RUNNING → COMPLETED / TIMED_OUT / CANCELLED

### 集成

`fastapi_app.py` 中 `_process_chunk_sync` 和 `_process_chunk_background` 末尾调用:
```python
get_task_manager().submit(meeting_id, _doc_runner)
```

## 八、经验蒸馏 (experience)

**设计文档**: [ADR-0043](../decisions/0043-experience-distillation.md)

### 问题

"用了这么多次 VPBuddy, 每次新会议它都像第一次跟我开会一样。"

### 方案

会议结束后从 MeetingState 自动提取经验候选, 存储为 JSON 文件, 支持检索和手动确认。

### 数据模型

`ExperienceItem` 6 种 kind:
- `domain_fact`: 领域事实 (来自 requirements)
- `product_pattern`: 产品模式 (Phase 2)
- `decision_rule`: 决策规则 (来自 goals)
- `terminology`: 术语 (Phase 2)
- `failure_lesson`: 失败教训 (来自 risks)
- `user_preference`: 用户偏好 (Phase 2)

### 存储

```
data/experiences/
  {meeting_id}.json   # 每会一文件, 含候选列表
  _all.json           # 聚合索引, 仅含 approved=True
```

### 提取时机

`POST /api/meetings/{id}/close` 中自动调用:
```python
items = extract_from_meeting_state(meeting_id, state, meeting_title=meeting_id)
if items:
    save_experiences(meeting_id, items)
```

### 与 Chroma RAG 的关系

- Chroma RAG: **文档级检索** (上传文档、会议纪要全文)
- Experience Store: **经验级检索** (结构化可复用知识)

## 九、FastAPI 迁移

**设计文档**: [ADR-0044](../decisions/0044-fastapi-migration.md)

### 问题

`BaseHTTPRequestHandler` 手写路由存在 CORS/SSE/参数校验的安全和正确性问题。

### 方案

新增 `fastapi_app.py` (FastAPI 应用) 作为 BFF API 层, 旧 `ui_server.py` 保持双兼容。
