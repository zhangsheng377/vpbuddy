# ADR-0038 — 公网 GPU 服务器 47.100.182.3 部署规范

**状态**: **已接受** (2026-07-03)
**日期**: 2026-07-03
**作者**: Hermes (起草) / 张胜东 (决策)
**替代**: 无 (前向补充, 不取代任何 ADR; 衔接 ADR-0010 部署信息隔离 + ADR-0011 HF 模型离线 + ADR-0036 e2e GPU server)
**依赖**: ADR-0009 (Hermes 运行时) / ADR-0011 (HF 模型离线铁律) / ADR-0019 (Chroma RAG) / ADR-0036 (e2e 策略 GPU server) / ADR-0037 (v0.8.4 release)

## Context

张胜东 2026-07-03 上午给 Hermes 一台公网 GPU 服务器:
- **公网 IP**: `47.100.182.3` (Windows + WSL2 + Docker 容器, 实际部署点在容器 `45a0068d7784` 内)
- **GPU**: NVIDIA GeForce RTX 3090 (24GB, CUDA 12.6, Driver 560.94)
- **端口**: 宿主 16159 → 容器 22 (SSH); 宿主 28765 → 容器 8765 (UI)
- **根密码**: `[REDACTED]` (用户明确拒绝改, 决策保留现状)
- **持久化**: 容器 `/data` 挂宿主 Windows D:\ 盘 (9p drvfs, 非云盘)

任务: 把 vpbuddy-server **v0.8.4** (刚 tag 的 release) 部署上去, 让张胜东从公网直接 `http://47.100.182.3:28765/` 访问, 不依赖家庭 LAN (`http://192.168.10.63:8765`, V 家网 IPv4 单栈访问不到 ADR-0036 提到的 IPv6 域名)。

## Decision

### 1. 容器选择 + 持久化目录

不走 `setup_gpu.sh` 的 conda 路线 (容器系统 Python 3.10 不满足 `requires-python>=3.11`):

- 走 apt `python3.11` (Ubuntu 22.04 自带 `python3.11.0~rc1`) + venv
- Venv 在 `/data/vpbuddy/venv/`, 容器重建不丢
- 全部模型 / 数据 / 日志走 `/data/vpbuddy/` 子目录
- `/root/.cache/{huggingface,chroma}` **symlink** 指向 `/data/vpbuddy/cache/`, 让 stdlib cache 自动走持久化路径 (避免 cp -al 跨设备失败)

### 2. GPU 库版本匹配 driver

默认 `pip install vpbuddy[gpu]` 拉 `torch==2.12.1+cu130`, 容器 driver 12060 只到 CUDA 12.6, `cuda.is_available()=False`:

- 卸 cu130 wheel
- 装 `torch==2.5.1+cu124 torchaudio==2.5.1+cu124` 走 `https://download.pytorch.org/whl/cu124`
- 验证 `torch.cuda.is_available()=True` + tensor 加减乘 on GPU

**结论**: 跟 driver CUDA 版本匹配的 wheel, 别赌 cu13 wheel 兼容老 driver。

### 3. pip 镜像源

`pypi.org` 国内 timeout, `/etc/pip.conf` 改成阿里源 (`https://mirrors.aliyun.com/pypi/simple/`); torch wheel 走 `download.pytorch.org/whl/cu124` (阿里不全)。

### 4. HF 模型离线铁律 (ADR-0011 一致性)

`/data/vpbuddy/.env` 强制 `HF_HUB_OFFLINE=1` + `TRANSFORMERS_OFFLINE=1`, 启动时**不联网**:

- `paraphrase-multilingual-MiniLM-L12-v2` (4.1GB) 走 `hf-mirror.com` 预下
- `iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-pytorch` (990MB) 走 `modelscope` 阿里云镜像
- `pyannote/{segmentation-3.0, speaker-diarization-3.1, wespeaker-voxceleb-resnet34-LM}` 走 modelscope (3 模型 42MB)
- `chroma` 内置 fallback `Xenova/all-MiniLM-L6-v2` 走 hf-mirror 预下 6 个 onnx 文件到 `/data/vpbuddy/cache/chroma/onnx_models/`

### 5. vpbuddy ui_server 路径修复

默认 `VPBUDDY_UI_DIR=/home/zsd/vpbuddy/ui`, 容器内不存在报 500:

- env 改 `VPBUDDY_UI_DIR=/data/vpbuddy/server/ui`
- 这条**未来要 PR 修进 vpbuddy**, 让 `ui_server` 默认从 `__file__` 解析 (`Path(__file__).parent / "ui"`), 而不是硬编码 `/home/zsd/vpbuddy/ui`

### 6. 进程守护 (无 systemd)

容器内 PPID=1 是 sshd, 没 systemd:

- `nohup python -m vpbuddy.ui_server --host 0.0.0.0 --port 8765 > /data/vpbuddy/logs/ui.log 2>&1 &`
- `nohup python -m vpbuddy.sub_session_controller > /data/vpbuddy/logs/controller.log 2>&1 &`
- `echo $! > /tmp/vpbuddy_ui.pid` / `/tmp/vpbuddy_controller.pid`
- `disown` 让进程脱开 ssh session
- 启停脚本 `/usr/local/bin/{vpbuddy-start,vpbuddy-stop,vpbuddy-ui-start}.sh`

### 7. v0.8.4 版本显示 (.git 跨公网传输)

容器内 vpbuddy 源码 tar 出去没 `.git/`, `_version.py` fallback `"0.8.3"` (跟 v0.8.4 release 不符):

- 本地 tar `.git/` (31MB) → split 16 × 2MB → scp 到远端 → cat 拼回 → 解 tar (md5 校验)
- 容器内 `git describe` 报 "dubious ownership" (tar 出来的所有权是 1000:1000, 容器内是 root:root)
- `git config --global --add safe.directory /data/vpbuddy/server` 修
- UI 启动 banner 验证: `🏷️ VPBuddy UI server version: v0.8.4-modified` ✅

### 8. SSH 安全 (用户决策)

用户明确拒绝改密码:

- **保留** root 密码认证 (用户拒绝改, 不动)
- **额外** 生成 ed25519 key (`~/.ssh/hermes_47.100.182.3_ed25519`), key 登录验证
- `sshd_config` **没改** `PasswordAuthentication no` (用户拒绝)
- 风险: 公网 16159 端口密码认证开放 → 应**只对白名单 IP 开放** (待办, 见下文)

## 为什么这么改

- **Python 3.11 venv** 跟 ADR-0010 (deployment clean install) 一致 — 不用 conda 不污染系统, venv 删了重装快
- **torch cu124** 跟 ADR-0009 (Hermes 运行时) 一致 — 部署驱动, 不为 dev 方便妥协 (铁律 5)
- **HF 离线** 跟 ADR-0011 一致 — 模型一旦预下, 生产必须 offline, 不能让 vpbuddy 启动时联网
- **UI_DIR env fix** 跟 ADR-0037 (v0.8.4 release) 一致 — 部署环境差异不能写死路径, 留 env override
- **nohup + PID 文件** 跟 ADR-0036 (e2e GPU server) 一致 — 容器无 systemd 是普遍限制, 不是这台特殊
- **公网 28765 端口** 是张胜东**明确要求**, 决策保留; 不是设计选择, 是用户偏好

## Consequences

### 积极

- vpbuddy-server v0.8.4 公网可访问, 张胜东从公司 / 客户现场直接用, 不依赖家庭 LAN
- /data 持久化, 容器重建不重下 6GB 模型 (节省部署时间 30+ 分钟)
- HF 离线模式, UI 启动不再依赖 hf-mirror / huggingface.co 网络抖动
- 启停脚本化, 容器重启后 `vpbuddy-start.sh` 恢复服务

### 风险 / 待办

1. **公网 28765 / 16159 端口开放**: 跟张胜东确认是否需白名单 IP (防火墙 / 安全组), 当前**裸奔**
2. **VPBUDDY_UI_DIR env fix** 应 PR 进 vpbuddy 主仓, 让 ui_server 默认从 `__file__` 解析 ui 路径 (部署代码)
3. **PYANNOTE_LOCAL_DIR** 没设, pyannote.audio 推理时**不会**自动读 `/data/vpbuddy/cache/modelscope/pyannote/`, 需要后续 prod 用前补 env + 可能改 `vpbuddy/audio_diarization.py` 走 `ModelScope` 优先
4. **`vpbuddy_controller` 跑 LLM 6 doc**: 容器内 `ollama` 0.24.0 没跑模型 + `HERMES_API_KEY` 未设 → 6 doc 生成会 fallback 失败 (controller 不崩, 但产物空), 当前只验证 controller 进程 alive
5. **AGENTS.md §八 CI Node 20 deprecation warning**: GitHub Actions 已 deprecate Node 20, 需升 Node 24 (独立 PR)
6. **vpbuddy-client `tauri.conf.json` 版本号** 仍 v0.8.0, 需同步 v0.8.4 (跟 ADR-0035 client-version-mismatch 相关)

## 操作记录

```bash
# 1. apt + 持久化目录
apt install -y python3-pip git curl ffmpeg
mkdir -p /data/vpbuddy/{meetings,kb,uploads,logs,cache/{chroma,sentence-transformers,funasr,huggingface,modelscope}}

# 2. venv + 依赖
python3.11 -m venv /data/vpbuddy/venv
/data/vpbuddy/venv/bin/pip install -e "/data/vpbuddy/server[gpu]"  # 阿里源
/data/vpbuddy/venv/bin/pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cu124

# 3. HF cache symlink
ln -sf /data/vpbuddy/cache/huggingface /root/.cache/huggingface
ln -sf /data/vpbuddy/cache/chroma /root/.cache/chroma

# 4. 模型预下 (Python 走 snapshot_download)
snapshot_download("iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-pytorch")
snapshot_download("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")
snapshot_download("pyannote/segmentation-3.0")
snapshot_download("pyannote/speaker-diarization-3.1")
snapshot_download("pyannote/wespeaker-voxceleb-resnet34-LM")

# 5. .env + 启进程
cat > /data/vpbuddy/.env << EOF
VPBUDDY_DATA_DIR=/data/vpbuddy/data
VPBUDDY_DOCS_DIR=/data/vpbuddy/server/docs
HF_HOME=/data/vpbuddy/cache/huggingface
HF_HUB_OFFLINE=1
MODELSCOPE_CACHE=/data/vpbuddy/cache/modelscope
VPBUDDY_UI_PORT=8765
VPBUDDY_UI_DIR=/data/vpbuddy/server/ui
EOF

# 6. UI + controller
nohup /data/vpbuddy/venv/bin/python3 -m vpbuddy.ui_server --host 0.0.0.0 --port 8765 \
  > /data/vpbuddy/logs/ui.log 2>&1 &
echo $! > /tmp/vpbuddy_ui.pid

nohup /data/vpbuddy/venv/bin/python3 -m vpbuddy.sub_session_controller \
  > /data/vpbuddy/logs/controller.log 2>&1 &
echo $! > /tmp/vpbuddy_controller.pid

# 7. .git 传输 + safe.directory
tar -cf /tmp/vpbuddy_git.tar -C /home/zsd/vpbuddy .git
split -b 2m /tmp/vpbuddy_git.tar /tmp/git_part_
scp /tmp/git_part_* root@47.100.182.3:/tmp/
ssh root@47.100.182.3 "cat /tmp/git_part_* > /tmp/vpbuddy_git.tar && tar -xf /tmp/vpbuddy_git.tar -C /data/vpbuddy/server"
ssh root@47.100.182.3 "git config --global --add safe.directory /data/vpbuddy/server"
```
