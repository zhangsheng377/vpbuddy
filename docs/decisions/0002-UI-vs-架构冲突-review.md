# ADR-0002: VPBuddy UI vs 架构冲突 Review

- **状态**: Accepted
- **日期**: 2026-06-20
- **作者**: 张胜东 (起草: Hermes)
- **关联**: [ADR-0001 MVP 选型](./0001-MVP-选型.md)

---

## 背景

总体架构 v1.15 已迭代完成,但 **UI 截图 (`ui-mockups/` 目录) 跟架构严重脱节**——用户在 2026-06-20 review 8 张 UI 截图后发现:

| # | 严重程度 | UI 现状 | 架构态度 | 影响 |
|---|---|---|---|---|
| 1 | 🔴 严重 | 6 张 UI 都有"投屏"按钮(投屏编辑结果/投屏架构结果/加入投屏内容/投影演示/投屏聚焦结果) | v1.10 已删,VP 自己点会议客户端 | UI 严重落后 |
| 2 | 🔴 严重 | Agent 数量 5/6 不一致(UI02=5 个,UI06=6 个) | 架构规定 5 个,产品说明书也 5 个 | 数量冲突 |
| 3 | 🔴 严重 | Agent 名字不统一(UI 用"合规与审计""数据建模""开发任务") | 架构/产品说明书规定"产品/架构/UI/数据/风险" | 心智模型混乱 |
| 4 | 🔴 严重 | "AI 建议提问"合并了 v1.11 的"疑问窗口+预准备内容"2 模块 | v1.11 加了 2 个独立模块 | 丢掉 v1.11 核心改动 |
| 5 | 🟡 中等 | 6 项交付物清单不一致(UI02 v1/v2 顺序不同) | 未明确定义 | UI 不一致 |
| 6 | 🟡 中等 | UI01 命名为"登录",实际是"加入会议" | n/a | 命名错误 |
| 7 | 🟡 中等 | 状态标签混乱(已生成/生成中/更新中/计划中) | v1.14 只规定 4 个 status | UI 状态过多 |
| 8 | 🟡 中等 | "仅 VP 可见"按钮(所有 UI 顶部) | 架构未明确 | UI 私有功能 |
| 9 | 🟢 轻微 | 顶部 "加入会议" 按钮带下拉箭头 | 仅 UI01 有 | UI 不一致 |

UI 是**最原始的,产品经理自己瞎画的**——用户原话。这套 UI 是 v1.7 之前的旧设计,没跟上 v1.10/v1.11/v1.13/v1.14/v1.15 的改动。

---

## 决策

### 决策 1:UI 完全重做(Linear Dark 风格)

**选项 A(已选):用 `claude-design` + `popular-web-designs` skill 重做,出 `ui-mockups/v2/` 子目录**

**理由**:
- UI 落后太多(8 张图都有问题),patch 不如重做
- `claude-design` 出 HTML(可点击原型,接近真实体验)
- `popular-web-designs` 提供 54 个真实设计系统参考(选 Linear 适配深色 SaaS 工作台场景)
- 重做后保留旧 UI 在 `ui-mockups/v1-archive/`(可对比)

**选项 B(未选):逐张用画图工具改 PNG**
- ❌ 8 张图都要改,工作量巨大
- ❌ 画图工具改 UI 不灵活(改完发现不对,还要再改)
- ❌ HTML 原型可点击验证,PNG 只能看

**已落地**:`ui-mockups/v2/01-linear-dark/index.html`(32.9KB,3 个 screen)

### 决策 2:6 项交付物清单固定(v1.16)

**6 项固定**(MVP 阶段禁止增减):

| # | 交付物 | 主责 Agent | 关键内容 |
|---|---|---|---|
| 1 | 交互 Demo | UI Agent + 产品 Agent | 可点击的 HTML/React 原型 |
| 2 | 需求清单 | 产品 Agent | 编号需求 + 优先级 + 状态 + 关联客户原话 |
| 3 | 技术架构 | 架构 Agent | 模块图 + 技术选型 + 关键风险标注 |
| 4 | 任务拆解 | 产品 Agent + 风险 Agent | 任务卡片 + 工期 + 依赖 |
| 5 | API 设计 | 数据 Agent | OpenAPI / GraphQL schema + 字段说明 |
| 6 | 风险分析 | 风险 Agent | 风险清单 + 缓解方案 + 合规审计 |

**为什么是 6 项**:
- 太少(3 项)覆盖不全(光 Demo 没有数据模型/API/任务,客户问"工期多少"答不上)
- 太多(10+ 项)信息过载,VP 看不过来
- **6 项 = VP 一次会议能 review 的上限**(认知研究:7±2 短时记忆容量)

### 决策 3:Agent 名字锁定 5 个(v1.16)

**5 个固定**(UI/产品说明书/ADR 必须统一):

| Agent | 关注 | 输出 |
|---|---|---|
| **产品** Agent | 业务目标、用户故事、PRD 风格 | 用户故事 / 业务流程图 / 原型建议 |
| **架构** Agent | 技术选型、模块划分、接口 | 架构图 / 技术栈 / 关键风险 |
| **UI** Agent | 页面布局、交互流程、视觉 | 页面 wireframe / 组件树 / 交互稿 |
| **数据** Agent | 数据模型、字段、关系、API | ER 图 / API 契约 / 数据流 |
| **风险** Agent | 性能/安全/合规/工期 | 风险清单 / 缓解方案 / 工期估算 |

**禁止改名**(破坏心智模型):
- ❌ "风险 Agent" → "合规与审计 Agent"(UI06 旧错)
- ❌ "数据 Agent" → "数据建模 Agent"(UI02 旧错)
- ❌ "数据 Agent" → "数据建模 Agent" + "开发任务 Agent" → 5 个变 6 个

### 决策 4:UI 重做的设计原则(Linear Dark)

- **深色原生**:`#08090a` 背景,不是 dark theme applied to light
- **半透明白边**:`rgba(255,255,255,0.08)` 而非实色
- **Inter Variable 510 weight**:Linear 标志性 between-weight(比 500 轻,比 400 重)
- **content-density**:信息密度高,VP 一次能扫很多内容
- **状态 3 态**:`done / generating / idle`(替代 v1 的 8 个标签)

### 决策 5:投屏 100% 不在 UI(确认)

**v1.10 已删,v1.16 强化**:
- ❌ VPBuddy UI 不提供投屏按钮
- ❌ VPBuddy 不实现投屏 SDK
- ✅ VP 想跟客户分享 → VP 在会议客户端(飞书/腾讯/钉钉/Zoom)自己点"共享屏幕"

### 决策 6:4 窗口 VP 视角(确认)

| 窗口 | 谁主动 | 谁决定 | UI 颜色 |
|---|---|---|---|
| **疑问窗口** | AI | VP 看/回 | 蓝紫(#7170ff dot) |
| **预准备内容** | AI | VP 用/不用 | 绿(#10b981 dot) |
| **Steer 入口** | VP | VP 显式 | 黄(#f59e0b dot) |
| **外发动作** | VP | VP 显式 | 灰(#62666d dot) |

## 后果

### 正面影响
- ✅ **UI 跟架构完全对齐**(消除 3 个 🔴 严重冲突)
- ✅ **6 项交付物清单锁定**(防止后续 UI 又自由发挥)
- ✅ **5 Agent 名字锁定**(防止心智模型漂移)
- ✅ **HTML prototype 可点击验证**(比 PNG 更接近真实体验)
- ✅ **设计系统可复用**(Linear Dark 风格可扩展到所有 UI)

### 负面影响 / 风险
- ⚠️ **旧 UI 截图要废弃**:8 张 PNG 全部移到 `v1-archive/`,UI 设计师要重新画
- ⚠️ **后续 UI 必须用 HTML prototype 流程**:不能直接画 PNG(避免同样的脱节)
- ⚠️ **UI 重做工作量**:从 0 到 v1 大概要 2-3 天(用户验收 + 精修)

### 缓解措施
- **保留旧 UI 截图**(在 `ui-mockups/v1-archive/`),便于对比
- **建立 UI 更新规则**:架构改 v1.X+1 → 必须同步更新 UI;否则视为"UI 过期"
- **后续 UI 用 claude-design skill**:避免产品经理自己瞎画

## 替代方案

### 替代 1:逐张改 PNG
- ❌ 工作量大(8 张 × 画图工具)
- ❌ 不灵活(改完发现不对,还要再改)
- ❌ PNG 不可点击

### 替代 2:不重做,只在架构里删"投屏"
- ❌ UI 还在,用户还是看到投屏按钮
- ❌ 其他 6 个问题没解决

### 替代 3:用 Vercel Light 风格
- ✅ 数据密集场景更合适(白底 + 高对比)
- ❌ VPBuddy 现有 UI 是深色,产品经理可能更喜欢深色
- 💡 **下一步**:可以出 Vercel Light 对比版,让用户选

### 替代 4:Agent 数量改成 6 个
- ❌ 跟产品说明书冲突,产品说明书定义 5 个
- ❌ 改产品说明书工作量更大
- ❌ 心智模型破坏

### 替代 5:交付物清单改成 8 项
- ❌ 8 项信息过载,VP 看不过来
- ❌ 跟原 UI 的 8 项列表(交互Demo/页面结构/功能流程/数据模型/API设计/权限模型/开发任务/工期)对齐但过载

## 后续 UI 更新规则

1. **架构版本变化(v1.X+1)→ UI 必须同步更新**
2. **UI 用 claude-design skill 出 HTML prototype**(不是产品经理瞎画)
3. **HTML prototype 验收后再转 PNG**(可选,用于截图分享)
4. **旧 UI 移到 `v1-archive/` 保留历史**
5. **重做的 UI 必须在 README 里写 v1 差异表**(便于 review)
