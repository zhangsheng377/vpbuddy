# ADR-0039 — 客户端默认 GPU server URL 切公网 47.100.182.3

**状态**: **已接受** (2026-07-03)
**日期**: 2026-07-03
**作者**: Hermes (起草) / 张胜东 (决策)
**替代**: 无 (前向变更, 不取代任何 ADR; 衔接 ADR-0038 公网部署规范)
**依赖**: ADR-0038 (公网 GPU 服务器 47.100.182.3 部署规范) / ADR-0036 (e2e GPU server) / ADR-0037 (v0.8.4 release)

## Context

2026-07-03 上午张胜东把 vpbuddy v0.8.4 部署到公网 GPU 服务器 `47.100.182.3:28765` (ADR-0038), 公网 UI HTTP 200 + controller running, 真链路通了。

但客户端 (Tauri 桌面端 + 内嵌 `ui/`) 的内置默认 GPU URL 还是**老的家庭 LAN 域名**:

| 位置 | 行 | 值 |
|------|----|----|
| `vpbuddy-client/ui/main.js` (前端 fallback) | 92 | `http://gpu.zhangshengdong.com:8765` |
| `vpbuddy-client/src-tauri/src/main.rs` (Rust 启动 fallback) | 168 | `http://gpu.zhangshengdong.com:8765` |
| `vpbuddy-client/src-tauri/src/main.rs` (yaml 模板 fallback) | 431 | `http://gpu.zhangshengdong.com:8765` |

**症状**: 张胜东在任何机器上**第一次**装 vpbuddy-client v0.8.4, 没改过 `~/.vpbuddy-client.yaml` 也没设 `VPBUDDY_GPU_URL` 环境变量, 客户端会去连老 LAN 域名 `gpu.zhangshengdong.com`, 触发 ADR-0036 提到的 IPv6 解析失败 (V 家网 IPv4 单栈访问不到 AAAA-only 域名), 然后端口也错 (8765 是 LAN 端口, 公网是 28765)。

**用户决策**: 把内置默认值直接改成公网 `http://47.100.182.3:28765`, 装上客户端默认就能连上, 不用先去设置页改 URL。

## Decision

### 1. 内置默认值统一改为公网 URL

3 处内置默认值 (`main.js:92` / `main.rs:168` / `main.rs:431`) 全部改为:

```
http://47.100.182.3:28765
```

yaml 模板文件 (`open_config_dir_cmd` 第一次运行时生成的 `~/.vpbuddy-client.yaml`) 也走这个新默认值, 老 yaml 文件不动 (用户的 `gpu_server_url` 覆盖优先级仍生效)。

### 2. 优先级链不变

保留 `main.rs:163-168` 注释的优先级链:

```
VPBUDDY_GPU_URL (env var) > ~/.vpbuddy-client.yaml > 内置默认值
```

+ `main.js:84-93` 注释的 localStorage 优先 (用户设置页改过 → 写回 yaml + localStorage):

```
localStorage > invoke("get_gpu_url") > 内置默认值
```

老 LAN 域名 `http://gpu.zhangshengdong.com:8765` **保留**在 `ui_server.py:1902` 注释 (解释为什么不能用 IPv6-only 域名), 客户端代码里完全不再出现。

### 3. UI 描述同步更新

`vpbuddy-client/ui/index.html:196` 设置页的优先级说明文字, "内置域名 (gpu.zhangshengdong.com)" 改为 "内置默认值 (47.100.182.3:28765)"。

`src-tauri/src/main.rs:988` 启动 log "默认, 无 yaml" 的显示也同步。

### 4. 不做的事

- ❌ **不** 删除 `gpu.zhangshengdong.com` 域名解析 (DNS 那边张胜东自己控制, 跟代码无关)
- ❌ **不** 给客户端加 "公网/内网" 模式切换 UI (单默认值更简单, 切回内网时让用户改设置页即可)
- ❌ **不** 改 `ui_server.py:1902` 注释 (那是历史教训, 留作记录)
- ❌ **不** 改 e2e fixture 默认 (那些走 env var, 跟客户端默认值是两个东西)

## Consequences

### 正

- 张胜东 (或任何用户) 第一次装 v0.8.4 客户端, 立即能用, 不需要先点设置页改 URL
- 公网部署 (ADR-0038) 真正 "端到端可用", 不只是服务端跑得起来
- 优先级链没动, 高级用户 (内网调试 / 测试环境) 仍可 env var / yaml 覆盖

### 负

- 家里 LAN 环境 (`192.168.10.63:8765`) 用户必须**显式**改设置页才能用, 不再 "开箱即用"
  - 缓解: 文档里说清楚 (产品说明书 + 部署文档加一行)
- 内置默认值跟客户端代码**绑定**, 后续换服务器要发新版本
  - 缓解: ADR-0038 部署文档是单一真实源, 客户端默认值改动走 ADR 流程

## Alternatives Considered

### A. 客户端加 "首次启动向导" 弹窗让用户填 URL

- 拒: 多 1 步, 跟当前 v0.8.x "装上即用" 体验不一致; 隐私敏感 (用户不一定想点窗口)

### B. 保留老 LAN 默认, 公网 URL 走 `VPBUDDY_GPU_URL` env var

- 拒: 张胜东 LAN 公网 2 套都要用, 让用户每次切都 export env 不现实; 默认值 = 公网更直接

### C. 客户端内置公网 + LAN 双默认 + 自动探测 (ping / 路由表)

- 拒: 复杂度暴涨, 探测逻辑难测, 失败回退 UX 差; 真切换让用户改 1 行 yaml 就行

## Verification

- `grep -rn "zhangshengdong" vpbuddy-client/` 应只剩 `index.html` 描述 + main.js 注释里**没有**这个域名 (只在内置默认值提及, 已替换)
- `grep -rn "47.100.182.3:28765" vpbuddy-client/` 应命中 3 处内置默认值 + 1 处描述
- 客户端冷启动 (删 ~/.vpbuddy-client.yaml + 删 localStorage) 应直接连公网 → `/api/status` 返回 200
