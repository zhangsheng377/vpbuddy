# 0023. chat 页面支持文件/图片上传 + agent 主动提问

- **状态**: 已接受 (2026-07-01 反转 — 原先标"跳过", 用户反悔要做)
- **日期**: 2026-07-01
- **作者**: 张胜东 (起草: Hermes)
- **替代**: 无 (新增)
- **依赖**: [ADR-0014](./0014-VPBuddy装成Hermes-Skill.md) (子 session 架构) · [ADR-0020](./0020-知识库-废弃旧库-文件上传-会议隔离.md) (KB 上传 API)

## 背景

2026-07-01 张胜东需求:
- "chat 页面那缺少上传文件/图片的按钮"
- "chat 页面要允许 agent 自动提问"

**当前状态**:
- Tauri 客户端 `vpbuddy-client/ui/index.html:114-124` `<section id="panel-chat">` 只有 `<textarea id="chat-input">` + `<button id="chat-send">`, **没有附件按钮**
- 服务端 `post_meeting_chat` (推断位置) 只接文本消息, 不接 multipart
- chat 行为: 用户发 → agent 答 (单轮), **agent 不能主动在 chat 留消息** (只能在 SSE 推 doc-update 等状态事件)
- 6 doc agent 完成时只推 `push_event(meeting_id, "doc-update", ...)`, chat 历史里看不到 agent "汇报"

## 决策

### 1. chat 页面加 📎 上传按钮 (文件 + 图片)

**改 `vpbuddy-client/ui/index.html:119-122` chat-input-row**:

```html
<div class="chat-input-row">
  <button id="chat-attach" title="上传文件/图片">📎</button>
  <input type="file" id="chat-file" multiple accept=".txt,.md,.pdf,image/*" style="display:none" />
  <textarea id="chat-input" placeholder="向 Hermes 提问, 或拖入文件"></textarea>
  <button id="chat-send">发送</button>
</div>
<div id="chat-attachments" class="chat-attachments"></div>
```

**上传交互** (`ui/main.js` 新 `attachFiles()` 函数):
- 点击 📎 → 弹文件选择 (原生 `<input type="file">` 或 Tauri `dialog.open`)
- 多选支持, 文件类型白名单: `.txt` / `.md` / `.pdf` / `image/*`
- 选完 → 显示在 `#chat-attachments` 区域 (缩略图 + 文件名 + 大小 + 删按钮)
- 点击 "发送" → 走 `uploadChatWithFiles(text, files)`:
  1. 先 POST 文本到 `/api/meetings/{id}/chat` (旧路径, 不变)
  2. 每个附件 → POST `/api/kb/upload` (复用 ADR-0020 的 KB 上传 API) + `meeting_id` 自动用当前会议
  3. 上传完成 → 在 chat 历史里 append 一条 user 消息: "📎 上传了 N 个文件: a.pdf, b.png → 已入 KB"
  4. 触发 agent 重新跑一轮 (可选, v0.6 一期不做, v0.7 加)

**图片预览**: 客户端加 base64 缩略图, 不上传到服务端 (省流量); 文本文件预览首 200 字符

### 2. 服务端 chat API 改造 (支持 multipart)

**改 `src/vpbuddy/ui_server.py` `post_meeting_chat` (推断路径)**:

```python
async def post_meeting_chat(meeting_id, request):
    content_type = request.headers.get("Content-Type", "")
    if content_type.startswith("multipart/form-data"):
        # 新: 文本 + 附件一起发
        form = await request.form()
        text = form.get("text", "")
        files = form.getall("files")  # list of FileField
        # 文件走 /api/kb/upload 同款逻辑 (内部调 rag_backend.add)
        for f in files:
            await kb_upload_handler(meeting_id, f)
        # chat 历史加 1 条 (user 消息, 含附件引用)
        chat_history.append({"role": "user", "text": text, "attachments": [f.filename for f in files]})
    else:
        # 旧: 纯 JSON 文本 (兼容)
        body = await request.json()
        chat_history.append({"role": "user", "text": body["text"]})
    
    # 触发 agent 答
    answer = await run_chat_agent(meeting_id, text, files=files)
    chat_history.append({"role": "assistant", "text": answer})
    
    return {"ok": True, "answer": answer, "attachments": [...]}
```

**注意**: 附件走 KB 入库, chat agent 答时**可以**通过 KB 检索 (调 `rag.query(where={"meeting_id": ...})`) 拉刚上传的文件内容 (ADR-0025 整合)。

### 3. agent 主动提问 (主动 chat)

**目标**: agent 完成工作时, 在 chat 历史里 append 一条 assistant 消息, 用户能直接看到。

**触发场景**:

| 触发 | 消息模板 |
|------|---------|
| 6 doc 全部 generated | "📄 6 文档已生成 (v1)。主要变更: {简述}。需要我开始 demo 制作吗？" |
| 风险命中 (5 类事实中 RISK 累计 >= 3) | "⚠️ 当前会议已记录 3 条风险: {list}。需要单独展开分析吗？" |
| demo 新版本生成 | "🎨 Demo v{N} 已生成: {一句话描述}。需要继续迭代吗？" |
| 用户 5 分钟没说话 (停顿检测) | "🤔 似乎大家在思考, 需要我总结一下当前累积的要点吗？" |
| 会议开始 10 分钟 (1/3 节点) | "⏱️ 会议进行 10 分钟, 已累积 N 个需求 / M 个风险。继续监看中..." |

**实现位置**: `src/vpbuddy/sub_session_controller.py` (6 doc agent 完成时) + 新 `src/vpbuddy/agent_proactive.py` (停顿 / 节点检测, 跑 background asyncio task)

**消息写入**:
```python
async def append_agent_chat(meeting_id: str, text: str, trigger: str):
    """agent 主动在 chat 历史里留话"""
    chat_history = storage.get_chat_history(meeting_id)
    chat_history.append({
        "role": "assistant",
        "text": text,
        "trigger": trigger,  # "docs_complete" / "risk_threshold" / "demo_new_version" / "silence" / "time_node"
        "is_proactive": True,  # 跟用户问的区分
        "created_at": datetime.now().isoformat(),
    })
    storage.save_chat_history(meeting_id, chat_history)
    # 推 SSE 让客户端刷新
    push_event(meeting_id, "chat-message", {
        "role": "assistant",
        "text": text,
        "is_proactive": True,
    })
```

**UI 区分 (`main.js`)**:
- 用户消息: 普通聊天气泡, 右对齐
- agent 答用户问题: 普通气泡, 左对齐
- **agent 主动**: 浅黄色背景 + 🤖 图标 + 折叠展开 (默认展开 1 行, 完整看点击)

**用户可关**: 设置页加 "agent 主动提问" 开关, 默认开

### 4. 触发频率控制 (避免刷屏)

| 触发 | 节流 |
|------|------|
| 6 doc 全部 generated | 1 次 / 会议生命周期 (6 doc 都重生成也算新事件, 推新消息) |
| 风险命中 | 1 次 / 会议生命周期 (达到阈值后, 后续 RISK 不再触发) |
| demo 新版本 | 1 次 / 版本 (新版本才触发) |
| 停顿检测 | 1 次 / 5 分钟 (5 分钟内不重复) |
| 会议节点 | 1 次 / 节点 (10 分钟 / 30 分钟 / 60 分钟各 1 次) |

实现: `_PROACTIVE_TRIGGERED` 内存 set, 记录 `(meeting_id, trigger_type)` 已触发过, 会议关闭时清空。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| agent 主动消息刷屏 (用户嫌烦) | 节流 set + 设置页可关 (默认开) |
| multipart 上传大文件 (50MB+) 卡 chat | 文件大小限制 10MB / 个 (KB 上传 50MB 单独, chat 附件更小) |
| agent 主动消息跟用户问题混淆 | UI 区分 (浅黄底 + 🤖 + is_proactive flag) |
| 停顿检测误触发 (用户只是翻文档, 不是停顿) | 一期简化: 5 分钟硬阈值 + 文字明确"似乎大家在思考", 用户能立刻分辨; v0.7 接 VAD 判真静音 |
