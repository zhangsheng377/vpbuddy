# ADR-0037 — v0.8.4 用户反馈修复 7 项

**状态**: **已接受** (2026-07-03)
**日期**: 2026-07-03
**作者**: Hermes (草稿) / 张胜东 (决策)
**替代**: 无 (前向补丁, 不取代任何 ADR)
**依赖**: ADR-0023 v1 (chat 上传 + 主动提问) / ADR-0028 (collab.md) / ADR-0032 (跨平台 loopback) / ADR-0036 (e2e 基础设施)

## Context

张胜东 2026-07-03 00:33 试 0.8.3 客户端 + GPU server (PID 1341250 + f4866c9 + `VPBUDDY_E2E=1`) 反馈 7 个问题:

1. 新会议一开始 6 个文档块就显示 vpbuddy demo 内容 (demo 块尤其烦), 还没说话就有内容看起来很怪
2. 5 个文档 (req/arch/tasks/api/risk) 格式极其繁琐, 200-1900 字节 boilerplate (YAGNI / state 比对表 / 变化判断逻辑)
3. Windows WASAPI loopback 没录到系统声 (v0.8.0 已实现, 但 Windows 平台仍 fallback mic), 用户摸不着头脑
4. 主动提问 (docs_complete / risk_threshold / demo_new_version / silence / time_node) 显示在 chat 框 (浅黄底), 应该是 🤝 协作疑问面板
5. chat 上传图片 + 说话, 服务端返 200 但内容空, UI 显示 "Hermes 已回复", 用户看不到真异常
6. demo 版本选择后 iframe 不跳转 (选老版本, SSE 推新版本又覆盖了)
7. KB 没上传按钮 + 检索返 5 个 undefined (字段名不匹配)

## Decision

7 项用户反馈全部接受, v0.8.4 release (git describe 0.8.3 → 0.8.4) 单独 commit, Tauri client + server 同步 bump:

### 1. 新会议 6 doc 块初始 placeholder
- `prompts/batch_docs.md` 改 "空 state (所有 facts 全空) → 跳过该文档, 不 write_file"; "state 累积无变化 → 跳过 5 docs 整批"
- `sub_sessions/batch_docs.py` 加 `state_empty` 判定, 空直接返回 `{"triggered": False, "skip": "empty_state_no_prior_docs"}` 不调 LLM
- 客户端 `vpbuddy-client/ui/index.html`: 6 块 (`req/arch/tasks/api/risk`) 初始 `doc-block-empty` placeholder: "暂无产物; 说话 / 上传文本后自动生成"

### 2. 5 docs 极简
- `batch_docs.md` 重写: <300 字极简, 砍"状态: 无变化"+ "YAGNI" + "state JSON 比对表" 等占位段; 空章节用单行 "(本会议暂无 X 需求)" 兜底

### 3. Windows 内录 banner
- 客户端 `index.html` 加 `#audio-warning` banner div; `main.js` 修 `updateAudioWarning` 函数 (合并老的 `updateLoopbackBanner` + 加 Windows v0.9.x 提示)
- 真支持仍走 cpal 升级 v0.9.x, 本轮仅 UI 提示

### 4. 主动提问 → collab 面板 (而非 chat)
- `agent_proactive.py.trigger()`: `_run_async` 改走 `collab.ask_question` (落 collab.md) + 推 SSE `collab-update`, **不**再写 chat.json + 推 chat-message
- 5 trigger 模板去掉 "需要继续选 demo 吗?" 等问句 (改为陈述事实 "🎨 Demo v2 已生成: 家庭档案")
- 客户端 `main.js renderChatMessage`: `is_proactive=true` 改 "💡 VPBuddy 提示" (灰色, 不显眼), 跟真问题 ("🤝 待答") 区分
- 单测改: `test_trigger_writes_chat_history` → `test_trigger_writes_collab_md_and_pushes_collab_update` 验证新路径

### 5. chat LLM 空响应 → 显式提示
- 客户端 `sendChat()` 在 `result.assistant_message.content` 空时显示 "⚠️ 服务器没返答 (error); 输入已记录", 不再假装成功
- 根因 (LLM 路由 qwen3:8b → minimaxi.com 返 400) 走 `VPBUDDY_LLM_API_BASE`/`VPBUDDY_LLM_MODEL` 环境变量修复, 本轮仅 UI 提示 (铁律 5 部署驱动)

### 6. demo 版本选择不被覆盖
- `main.js loadDemoVersion()`: 改用 `fetch()` 拉 HTML 内容写到 `iframe.srcdoc` (而非设 `iframe.src = URL`)
- 新增 `selectedDemoVersion` 变量跟踪用户选; SSE `doc-status kind=demo is_demo=true` 事件仅在 `selectedDemoVersion == demoVersions[0]?.version` 时自动更新 iframe, 用户主动选老版本不被 SSE 覆盖

### 7. KB 上传 + undefined 字段兼容
- `index.html` 加 `#kb-file` `<input type=file>` + `#kb-upload-btn` 按钮 (默认 disabled, 会议开始后启用)
- `main.js` 加 `kbSearch()` 函数, 用 `fetch()` 走 `/api/kb/search` 端点 (替 `invoke("kb_search")`, Tauri 2.6+ 兼容)
- render 兼容字段: `r.distance ?? r.score` / `r.snippet ?? r.text ?? r.document` / `meta.meeting_id ?? "?"` / `meta.doc_kind ?? meta.source ?? "kb"`

## 为什么这么改

- **6 docs 初始 placeholder** 跟 ADR-0022 (首页强制会议选择) 一致 — 会议开始后才有内容, 不创建 = 不显示
- **5 docs 极简** 跟 ADR-0029 (合并 6 sub-session → 2) 一致 — LLM 调用已经减少, 输出也精简
- **主动提问 → collab 面板** 跟 ADR-0028 / ADR-0030 一致 — "需要继续选 demo 吗" 不该刷 chat, 该当协作疑问处理
- **demo 版本选择不被覆盖** 跟 ADR-0024 (demo 多版本) 一致 — 用户主动选老版本是合理行为, 不要被 SSE 自动跳走
- **chat LLM 空响应** 用户层可见 — 假装成功是最糟体验

## 影响

- 服务端 `agent_proactive.py` 行为变更: 触发时不写 chat 历史 + 不推 chat-message
- 客户端 `main.js` 新增 `kbSearch` / `kbUpload` / `updateAudioWarning` / 修 `loadDemoVersion` / 修 `doc-status SSE listener` / 修 `renderChatMessage`
- Tauri client version `0.8.2` → `0.8.4` (cross-version 跳过 0.8.3 是 fix release)
- Server `0.8.3` → `0.8.4` (用 git describe, ADR-0035 模式)
- 单测 1 改 (`test_trigger_writes_chat_history` → `test_trigger_writes_collab_md_and_pushes_collab_update`) + `test_close_meeting_clears_proactive_throttle` 修 (monkeypatch 路径)
- e2e `test_agent_proactive.py` 中验证 role 🤖 → 💡 (行为变更)
- 0 product breaking change, 0 API breaking change, 行为变更客户可见

## 不在本轮修复

- Windows WASAPI loopback 真实现 → v0.9.x (cpal 升级暴露 cross-platform API)
- LLM 模型配置 (`VPBUDDY_LLM_API_BASE` env) → 用户在 GPU server systemd 服务配置
- 主动提问 questions.md 机制 → v0.9.x ADR-0023 v2
- KbStatus flake 5 个 test_deselect → pre-existing (3 个 test_sub_session fail 跟本轮无关)
