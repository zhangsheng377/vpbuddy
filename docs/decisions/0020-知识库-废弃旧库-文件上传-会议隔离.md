# 0020. 知识库方案废弃 + 文件上传 + 会议隔离

- **状态**: 已接受
- **日期**: 2026-07-01
- **作者**: 张胜东 (起草: Hermes)
- **替代**: [ADR-0015](./0015-RAG-sqlite-vec本地知识库.md) (Superseded by [ADR-0019](./0019-RAG-选型-Chroma-嵌入式.md))
- **依赖**: [ADR-0019](./0019-RAG-选型-Chroma-嵌入式.md) (RAG 选型)

## 背景

旧 KB 设计 (ADR-0015, 2026-06-23) 有 3 个核心问题:

1. **6 docs 自动 ingest 没意义**: 6 sub-session 写完的 req/arch/tasks/api/risk/demo 是"内部中间产物", 用户从未要求这些进 KB。`sub_session_controller.py:520-580` 的 `_kb_bg` background thread 自动调 `kb.add_document(meeting_id, doc_kind, content)`, 把所有 6 doc 全入库, 跨会议检索时混在一起, 命中率低 + 噪声大
2. **无会议隔离开关**: KB 列表里"SSO 走哪个 IdP"会命中所有会议, 没法按"当前会议"过滤。UI 端 `ui/index.html:247-255` `kb-kind` 只能按 doc_kind 过滤, 不能按 meeting_id
3. **KB 内容来源 = 系统自动**, 用户没有"上传文件进 KB"的入口, 完全被动

2026-07-01 张胜东拍板:
- **完全废弃旧 KB + 清旧 db** (不保留只读归档, 不双轨)
- **KB 内容来源 = 用户手动上传** (txt / md / pdf, 上传即入库)
- **KB 检索默认带 meeting_id 过滤** (跨会议需显式选"全部会议")
- **切分逻辑跟项目解耦** (ADR-0019 Chroma 嵌入式接管)

## 决策

### 1. 废弃 6 docs 自动 ingest 逻辑

**位置**: `src/vpbuddy/sub_session_controller.py:520-580` (整段 `_kb_bg` 删掉)

**改动**:
- 删 `from .knowledge_base import get_kb` 和相关 background thread 启动
- 6 doc 写完时**不再调** `kb.add_document()`
- 6 doc 写完的 SSE 推流**保持不变** (`push_event(meeting_id, "doc-update", ...)` + `check_all_docs_stored_and_close`)
- 会议关闭逻辑 (ADR-0018 切会议 / 关客户端) 保持不变, **不依赖 KB 入库状态**

**为什么废弃**: 6 doc 写完的产物本身已经存档到 `data/docs/{meeting_id}/{kind}.md` (供人看) + 已经通过 SSE 推到客户端 (供 VPBuddy 实时展示), 没必要再向量化存一份。"6 doc 怎么被检索"是另一个问题 (用户用 KB 是查"我以前给客户讲过什么" / "我们公司某产品背景", 不是查"上次会议的需求文档"), 应该让用户主动上传**会议外的资料** (产品手册 / 客户背景 / 行业报告)。

### 2. KB 内容来源 = 用户主动上传

**新 API**: `POST /api/kb/upload`

```
POST /api/kb/upload
Content-Type: multipart/form-data

Fields:
  meeting_id: str   (必填, KB 文档归属此会议)
  file: binary       (必填, .txt / .md / .pdf)
```

**后端处理**:
- 接 multipart → 保存到 `data/uploads/{meeting_id}/{uuid}_{filename}` (原始文件, 调试用)
- 切分: Chroma 默认按字符切 (sentence-transformer embedding 不要求预切, 框架内部处理短文本), VPBuddy 直接传 `documents=[整段文本]` 即可
- 入库: `rag.add(ids=[f"{meeting_id}:{uuid}:chunk_{i}"], documents=[chunk_i], metadatas=[{meeting_id, source, uploaded_at, chunk_index}])`
- 推 SSE: `push_event(meeting_id, "kb-doc-added", {doc_id, filename, chunks})`

**UI 入口**: 知识库页 (`vpbuddy-client/ui/index.html` panel-kb) 加 📎 按钮 → 弹文件选择 → 上传

**支持格式** (一期): `.txt` / `.md` / `.pdf` (Chroma 不解析 PDF, VPBuddy 用 `pypdf` 在上传时抽文本)

### 3. KB 检索默认带 meeting_id 过滤

**改动**: `kb.search()` → `rag.query(where={"meeting_id": current_meeting_id})`

**新 API**:
```
POST /api/kb/search
Content-Type: application/json

Body: {
  query: str,           # 必填
  top_k: int = 5,       # 默认 5
  meeting_id: str?      # 默认 = 当前会议 (从 SSE 连接 / UI 上下文取)
  scope: "current" | "all" = "current"   # "all" = 跨会议
}
```

**响应**:
```json
{
  "results": [
    {"id": "MTG01:abc:chunk_3", "meeting_id": "MTG01", "source": "upload:intro.pdf",
     "snippet": "...", "distance": 0.12, "chunk_index": 3},
    ...
  ],
  "scope": "current",
  "total": 5
}
```

**UI 改动** (`panel-kb`):
- 加 meeting_id 下拉条 (默认 = 当前会议, 选项 = "全部会议" + 已有会议列表)
- 跨会议 = 显式选 "全部会议" (scope=all), UI 警告"会检索所有会议资料"

### 4. 完全废弃旧 KB 库

**动作**:
1. 删 `src/vpbuddy/knowledge_base.py` 全部代码
2. 删 `src/vpbuddy/ui_server.py:555-557, 1551-1552` (旧 KB 调用)
3. 删 `src/vpbuddy/skill.py:9` (注释里 "委托 — 实际逻辑在 ... knowledge_base" 改 "rag_backend")
4. 删 `src/tests/test_knowledge_base.py` 全部
5. 删旧 `data/knowledge.db` 文件 (用户执行 `vpbuddy kb migrate --clean` 确认后清)
6. `pyproject.toml` 删 `sqlite-vec` 依赖
7. README 删旧"sqlite-vec + sentence-transformers 470MB"描述, 改"Chroma 嵌入式"

**不保留旧 KB 只读归档的理由**: 双轨 = 数据双源 = 检索时混两种 schema; 旧数据 6 doc 内容已经在 `data/docs/{meeting_id}/`, 人能看, 不需要再向量化存。

## 关键设计

### Metadata schema (ADR-0019 §关键设计 同步)

```python
{
    "meeting_id": "PHASE3_MEETING_REAL",   # 必填, 隔离用
    "source": "upload:customer_intro.pdf",  # 必填, 来源 (upload:<name> / paste / future agent)
    "uploaded_at": "2026-07-01T...",        # ISO 8601
    "chunk_index": 0,                       # 同一文件内第几段
    "file_size": 12345,                     # 原始文件大小
    "file_ext": "pdf",                      # 原始扩展名
}
```

### KB API 端点 (一期)

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/kb/upload` | POST | 上传文件进 KB |
| `/api/kb/search` | POST | 检索 (默认带 meeting_id 过滤) |
| `/api/kb/list` | GET | 列 KB 文档 (按 meeting_id 过滤) |
| `/api/kb/{doc_id}` | DELETE | 删 KB 文档 |

### 文件切分策略 (一期, Chroma 默认)

- `.txt` / `.md`: 整文件当 1 段 (文档通常 < 10KB, 切碎反而检索差)
- `.pdf`: `pypdf` 抽每页 → 每页当 1 段 (page-level chunk)
- 后续 v0.7+ 接 llama-index SentenceSplitter 做 token-level 切分 (用户没要求, 暂不做)

### 上传安全

- 文件大小限制: 50MB / file (避免 OOM)
- 文件类型白名单: `.txt` / `.md` / `.pdf` (避免可执行文件进 KB)
- 原始文件存 `data/uploads/{meeting_id}/` (跟 KB 库分离, 调试用, 不删)
- 抽文本走 try/except, 失败返回 400 + 错误信息
