# 0021. 桌面客户端支持麦克风 + 内录双轨 (跨平台)

> **📌 修订注 2026-07-02 (ADR-0032 取代)**: 本 ADR 当时误判 cpal 0.15 暴露 `wasapi::Device::is_loopback()` cross-platform API, **实际 cpal 0.15.3 源码确认只有 unsafe `windows-rs::IAudioRenderClient` 才能拿 render flow 设备**. v0.7.1 stub (ADR-0031) + v0.8.0 真实现 (ADR-0032) 走不同路线:
> - Linux: cpal `host.input_devices()` + 名字 `.monitor` 后缀匹配 (PulseAudio/PipeWire 约定)
> - macOS: cpal `host.input_devices()` + 名字含 `BlackHole`/`Loopback`/`Soundflower` 匹配
> - Windows: cpal 抽象层无 cross-platform API → v0.8.0 fallback mic + UI 强提示, v0.9.x unsafe 重构 (`IAudioRenderClient`)
> 
> 本 ADR 设计目标 (Tauri 客户端统一抽象麦克风 + 内录) 仍然正确, 实施细节见 ADR-0032.

- **状态**: 已接受 (2026-07-01) → 实施细节 superseded by [ADR-0032](./0032-Phase7-跨平台loopback真实现.md) (2026-07-02)
- **作者**: 张胜东 (起草: Hermes)
- **替代**: 无 (新增)

## 背景

2026-07-01 张胜东需求: "录音能录到电脑播放的声音吗？因为开会不光要录 VP 的发言, 也要录别人说的话, 从电脑音响里放出来的, 所以应该是麦克风 + 内录"。

**当前状态**:
- 服务端 `src/vpbuddy/loopback.py` 已实现 Linux PipeWire/PulseAudio 端到端录音 (`capture_loopback()`), 但**只支持服务端本地**, 不接客户端推上来的音频
- Tauri 客户端 `vpbuddy-client/src-tauri/src/audio.rs` 用 `cpal::default_host()` 拿**输入设备** (`host.input_devices()`), **只支持麦克风**, 不支持内录 (system audio output capture)
- Tauri 客户端 UI (`vpbuddy-client/ui/index.html:36`) 有 `#audio-device` 下拉, 但只列麦克风

**核心问题**: cpal 跨平台, 但内录 (loopback) 是**平台特定**操作:
- Linux: PipeWire monitor / PulseAudio monitor (已有 `loopback.py` 实现)
- macOS: 需装 BlackHole / Soundflower / Loopback (虚拟音频设备), cpal 能识别
- Windows: WASAPI loopback (Windows 10+ 内部 API, cpal 0.15 暴露 `host.input_devices()` 也能拿)

**目标**: Tauri 客户端**统一抽象**麦克风 + 内录, 跨平台自动适配, UI 提供开关。

## 决策

### 1. Tauri 后端加 loopback 支持

**改 `vpbuddy-client/src-tauri/src/audio.rs`**:

```rust
pub enum AudioSourceKind {
    Microphone,  // 默认
    Loopback,    // 系统内录
}

pub struct AudioCaptureConfig {
    pub source_kind: AudioSourceKind,
    pub device_id: Option<String>,  // None = 用平台默认
}

impl AudioCapture {
    pub fn new_with_config(config: AudioCaptureConfig) -> Result<Self> { ... }
}
```

**平台实现**:

| 平台 | Microphone | Loopback |
|------|-----------|----------|
| Linux | cpal ALSA / PipeWire default input | cpal 拿 `.monitor` 后缀设备, 或 `host.input_devices()` 枚举 |
| macOS | cpal CoreAudio default input | cpal 拿名字含 "BlackHole" / "Loopback" / "Soundflower" 的输入设备 |
| Windows | cpal WASAPI default input | cpal WASAPI loopback (cpal 0.15+ 用 `wasapi::Device::is_loopback()` 标记, 需建特殊 config) |

**平台检测 + 设备枚举 API**:

```rust
pub fn list_audio_sources() -> Vec<AudioSourceInfo> {
    // 返回 [{id, name, kind: Microphone|Loopback, is_default: bool}, ...]
    // Linux: 拿 ALSA / PipeWire 所有输入设备, 名字含 ".monitor" → Loopback
    // macOS: 拿 CoreAudio 所有输入设备, 名字含 "BlackHole" / "Loopback" / "Soundflower" → Loopback
    // Windows: 拿 WASAPI 所有输入设备, 标记 is_loopback() → Loopback
}
```

### 2. Tauri 命令加 source_kind 参数

**改 `vpbuddy-client/src-tauri/src/lib.rs`**:

```rust
#[tauri::command]
async fn start_capture(
    source_kind: String,  // "microphone" | "loopback" | "both"
    audio_device: Option<String>,
    auto_upload: bool,
) -> Result<String, String> {
    // source_kind="both" → 双 stream 混合 (内部 soxr 重采样后 mix)
    // source_kind="microphone"|"loopback" → 单 stream
}
```

**`source_kind="both"` 混合策略** (一期简化, v0.7+ 优化):
- 同时开 2 个 cpal Stream (mic + loopback)
- 各取 1s native 采样率 PCM
- 按时间戳对齐 → 简单线性加和 → 除以 2 (避免溢出) → 输出 1s 16kHz mono
- 注意: 当只开一个时 (如 macOS 没装 BlackHole, loopback 端空), 退化只用 mic, UI 提示

### 3. UI 加 source_kind 切换

**改 `vpbuddy-client/ui/index.html:32-37` rec-controls**:

```html
<div class="rec-controls">
  <button id="btn-rec" class="btn-rec" data-state="idle">开始录音</button>
  <label><input type="checkbox" id="auto-upload" checked /> 自动上传</label>
  <select id="audio-source-kind">
    <option value="microphone">麦克风 (默认)</option>
    <option value="loopback">系统内录</option>
    <option value="both">麦克风 + 内录</option>
  </select>
  <select id="audio-device"><option value="">默认设备</option></select>
</div>
```

**设备列表根据 source_kind 动态更新**:
- 选 "microphone" → `#audio-device` 只列麦克风设备
- 选 "loopback" → 只列内录设备 (Linux monitor / macOS BlackHole / Windows WASAPI loopback)
- 选 "both" → 列出全部 (mic + loopback), 用户各选 1 个, 但一期简化: 选 "both" 强制用默认 mic + 默认 loopback, 设备下拉禁用

### 4. 服务端 loopback 端到端备选保留

`src/vpbuddy/loopback.py` 已经存在, **保留作服务端备选** (开发机直跑, 不用客户端), 路径不变, 仅在 `docs/design/总体架构.md` 标注它是"开发备选"。

## 平台差异

| 平台 | 麦克风 | 内录 | 用户操作 |
|------|--------|------|---------|
| Linux (PipeWire) | ✓ 默认 input | ✓ 默认 sink 的 `.monitor` | 0 操作 |
| Linux (PulseAudio) | ✓ 默认 source | ✓ `pactl list sources` 找 `*.monitor` | 0 操作 |
| macOS | ✓ CoreAudio default input | △ 需装 BlackHole 2ch | 用户装 BlackHole (免费) |
| Windows | ✓ WASAPI default input | ✓ WASAPI loopback (cpal 0.15+ 暴露) | 0 操作 |

**注意**: macOS 内录**不是系统自带**, 必须装 BlackHole。这是 macOS 平台限制, VPBuddy 不绕过 (装 BlackHole 是 1 次性操作, 官方免费开源, https://github.com/ExistentialAudio/BlackHole)。

## 实施步骤

1. **改 `vpbuddy-client/Cargo.toml`**: cpal 升 0.15+ (支持 WASAPI loopback), 确认 cpal features `["wasm-bindgen"]` 不需要
2. **改 `vpbuddy-client/src-tauri/src/audio.rs`**:
   - 加 `AudioSourceKind` enum
   - 加 `AudioCaptureConfig` struct
   - 改 `new_with_device` → `new_with_config`
   - 加 `list_audio_sources()` 函数
   - macOS: 名字匹配 `"BlackHole" | "Loopback" | "Soundflower"`
   - Windows: 用 `wasapi::Device::is_loopback()` (需 cpal 0.15+ WASAPI backend)
   - Linux: 名字后缀 `.monitor`
3. **改 `vpbuddy-client/src-tauri/src/lib.rs`**:
   - `start_capture` 命令加 `source_kind` 参数
   - 加 `list_audio_sources` 命令 (前端拉设备列表)
   - `source_kind="both"` 走 `mix_two_streams` 内部函数
4. **改 `vpbuddy-client/ui/index.html`**: 加 source_kind 下拉 + 设备列表动态加载
5. **改 `vpbuddy-client/ui/main.js`**: `start_capture` 调 invoke 带 source_kind + audio_device, 启动时拉设备列表填下拉
6. **改 `vpbuddy-client/src-tauri/Cargo.toml` + `tauri.conf.json`**: bundle metadata (version 0.6.0, name 不变)
7. **测试**: `vpbuddy-client/src-tauri/tests/test_audio_source.rs` 跨平台 device 枚举
8. **CI**: 确认 GitHub Actions macOS / Windows runner 跑过编译 (之前只 Linux)
9. **同步更新**: `docs/design/总体架构.md` v1.21 + `docs/product-spec/VPBuddy_产品说明书.md` v2.0 (用户视角 "录音" 章节)

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| cpal 0.15 WASAPI loopback API 不稳 (rust crate 偶有 breaking change) | pin 具体 minor version (0.15.x) + CI 三平台都跑 |
| macOS BlackHole 装机率低, 用户不知道去哪装 | 客户端设置页加 "macOS 内录设置" 卡片, 链接到 BlackHole GitHub + 自动检测 (cpal 枚举含 "BlackHole" 设备时, UI 状态显示 "已就绪") |
| Windows WASAPI loopback 在某些声卡驱动上采不到声音 | 客户端加诊断 API: 录音前 1s 试采, 静音/异常时 UI 提示"内录采不到声音, 切换到麦克风?" |
| source_kind="both" 混合算法质量 (时间戳对齐 + 加权和) 难调 | 一期简化: 同时开 2 个 stream, 各自读 1s, 短端补零对齐, 等权平均 (即 `out[i] = (mic[i] + loopback[i]) / 2`)。质量差时 v0.7+ 再调 |
