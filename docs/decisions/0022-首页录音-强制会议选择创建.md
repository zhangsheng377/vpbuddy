# 0022. 首页录音流程 — 强制会议选择/创建

- **状态**: 已接受
- **日期**: 2026-07-01
- **作者**: 张胜东 (起草: Hermes)
- **替代**: 无 (新增)
- **依赖**: [ADR-0018](./0018-SSE-chunked-meeting-complete-stop语义.md) (会议关闭语义)

## 背景

2026-07-01 张胜东需求: "首页上点开始录音, 直接默认就是创建新会议了？不行哦, 还要弄个下拉条吧, 可以选择旧会议, 或者直接输入会议名就是新会议。没选择也不输入的话, 不给点开始录音。这样就算停止录音, 也不用停止会议"。

**当前状态**:
- Tauri 客户端 `vpbuddy-client/ui/main.js:107-110` `start_capture` 一调 = 自动创建新会议
- 没有"选旧会议 / 输入新会议名"的前置 UI
- 停止录音 = 当前逻辑下也是"停会议" (`stop_capture` 隐含 close_meeting)
- 会议关闭触发器 ADR-0018 写的是"6 docs 全 generated" → 推 meeting-complete + close_meeting

**核心问题**:
1. 用户开始录音时**没有选择权**, 默认行为不符合预期
2. **6 docs 完成 ≠ 会议结束**: 张胜东 2026-07-01 明确说 "6 doc 会不断迭代, 此时完成不代表会议要结束"
3. **会议真正结束 = 切会议 / 关客户端** (用户拍板)

## 决策

### 1. 首页录音 UI: 必须先选/输入会议

**改 `vpbuddy-client/ui/index.html:32-37` rec-controls**:

```html
<div class="rec-controls">
  <select id="meeting-select">
    <option value="" disabled selected>— 选择已有会议 —</option>
    <!-- 动态填 /api/meetings 列表 -->
  </select>
  <span style="color: var(--text-muted); font-size: 12px;">或</span>
  <input type="text" id="meeting-new" placeholder="输入新会议名 (3-32 字符)" maxlength="32" />
  <button id="btn-rec" class="btn-rec" data-state="idle" disabled>开始录音</button>
  <label><input type="checkbox" id="auto-upload" checked /> 自动上传</label>
  <select id="audio-source-kind">...</select>
  <select id="audio-device">...</select>
</div>
```

**按钮启用条件** (`main.js`):
- `meeting-select` 选了 (value != "") → 用旧会议, 启用按钮
- `meeting-new` 输入非空 (校验 3-32 字符, 不重名) → 用新会议, 启用按钮
- 都没选/没输入 → 按钮 disabled, 鼠标悬停 tooltip "请先选择已有会议或输入新会议名"
- 两个都填 → 优先用输入框 (新会议), UI 警告"将创建新会议 'XXX', 而不是用 'YYY'"

### 2. 会议 ID 校验

**`meeting-new` 校验规则** (`ui/main.js` 前端 + `lib.rs` 后端双重):
- 长度: 3 ~ 32 字符
- 字符: `[A-Za-z0-9_\-]+` (无空格, 无中文 — 简化 ID, 显示名走 `project_name` 字段)
- 不重名: 调 `GET /api/meetings/check_id?id=XXX` 返回 bool, 防跟已有会议冲突
- 错误提示: 实时显示在输入框下方 (红色), "会议名只能含字母数字下划线连字符, 长度 3-32"

### 3. 会议状态机调整 (核心改动)

**当前 (ADR-0018)**:
```
created → recording → 6 docs done → meeting-complete → close_meeting → closed
```

**新**:
```
created → recording → ... → (持续 recording, 6 doc 持续迭代) → ...
                              ↓
                        切会议 / 关客户端 / 用户手动 [结束会议]
                              ↓
                        meeting-complete → close_meeting → closed
```

**关键改动**:
- **6 docs 全 generated 不再触发 close_meeting** (用户拍板)
- **meeting-complete 触发器 = 切会议 / 关客户端 / 用户点 [结束会议] 按钮**
- 6 docs 全 generated **只** 推 SSE `docs-complete` 事件, UI 收到时显示 "✅ 6 文档已生成" 提示, 但**不关会议**
- 会议持续期间, 6 doc agent 监听新 transcript, 继续迭代 (修老 doc / 加新内容)

**后端 `sub_session_controller.py:check_all_docs_stored_and_close` 改**:
- 旧逻辑: 6 docs 全 stored → 推 `meeting-complete` + `close_meeting`
- 新逻辑: 6 docs 全 stored → **只** 推 `docs-complete` (新事件), 不调 close_meeting
- `close_meeting()` 改成只在用户主动触发时调 (UI 按钮 / 客户端断开 / 切会议)

### 4. 切会议 / 关客户端触发 close_meeting

**切会议** (`meeting-select.onChange`):
- 当前会议 → 调 `close_meeting(current_meeting_id)` → 推 SSE meeting-complete
- 选新会议 → 加载新会议历史 transcript + chat + 6 doc (从 `data/docs/{new_id}/`)

**关客户端** (Tauri `app.on_event(WindowEvent::CloseRequested)`):
- 遍历所有 active_meetings → 调 `close_meeting()` 每个
- 客户端进程退出

**用户手动 [结束会议] 按钮** (新增, 在 `rec-controls` 区):
- 仅当 `recording=true` 时显示 (录音中才能结束, 避免误触)
- 点击 → 调 `close_meeting()` → 推 SSE meeting-complete → 录音自动停

### 5. 会议状态展示 (UI)

**首页顶部 status 区** (改 `index.html:21-25`):
```html
<span class="status-pill" id="meeting-pill" title="当前会议">
  <span class="dot" id="meeting-dot"></span>
  <span id="meeting-status">未选会议</span>
</span>
```

**状态值**:
- 未选会议 (灰)
- 已选会议 — 待录音 (黄, 等待点开始录音)
- 录音中 (绿, 闪烁)
- 6 文档已生成 (蓝, 持续展示)
- 会议已结束 (灰, 推 SSE meeting-complete 后)

## 实施步骤

1. **改 `vpbuddy-client/ui/index.html:32-37`**: 加 meeting-select / meeting-new / meeting-pill / 结束会议按钮
2. **改 `vpbuddy-client/ui/main.js`**:
   - `loadMeetings()` 拉 `/api/meetings` 填下拉
   - `meeting-select.onChange` / `meeting-new.onInput` 控制 btn-rec disabled
   - `start_capture` invoke 改: 不再自动建会议, 接收 `meeting_id` 参数 (前端从下拉/输入框取)
   - 新增 `endMeeting()` 函数 → invoke `close_meeting`
   - 监听 SSE `docs-complete` + `meeting-complete` 事件
3. **改 `vpbuddy-client/src-tauri/src/lib.rs`**:
   - `start_capture` 加 `meeting_id: String` 参数 (必填)
   - `close_meeting` 新 Tauri 命令 → 调服务端 `close_meeting()` API
   - `app.on_event(WindowEvent::CloseRequested)` → 关闭前调 close_meeting
4. **改 `src/vpbuddy/ui_server.py`**:
   - 新端点 `GET /api/meetings/check_id?id=XXX` (校验重名)
   - 改 `close_meeting` 内部逻辑 (不再被 6 docs trigger, 只被显式调用)
5. **改 `src/vpbuddy/sub_session_controller.py:check_all_docs_stored_and_close`**:
   - 改名 `check_all_docs_stored_notify` (语义改: 只通知, 不关)
   - 6 docs 全 stored → 推 `docs-complete` SSE, **不**调 close_meeting
6. **改 `src/vpbuddy/realtime_server.py`** (推断): 加新事件类型 `docs-complete` (跟 `meeting-complete` 区分)
7. **测试**:
   - `tests/test_meeting_lifecycle.py` — 切会议触发 close_meeting
   - `tests/test_meeting_check_id.py` — 重名校验
   - `tests/test_docs_complete_not_close.py` — 6 docs 完成不关会议
8. **同步更新**: `docs/design/总体架构.md` v1.21 会议生命周期图重画, `docs/product-spec/VPBuddy_产品说明书.md` v2.0 用户视角 "开始录音" 章节
