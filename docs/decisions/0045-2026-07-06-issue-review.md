## 决策总览

### 核心原则

1. **先出能跑的，再做优化。** 核心流程（ASR → 增量清洗 → 文档生成）刚跑通，先稳住这个。
2. **不做用户管理。** VPBuddy 当前是单机桌面工具，无多用户场景。登录、手机号验证码、邀请码、SSO、token 鉴权全部不做。
3. **前端/后端边界分清。** 前端能本地管理的状态（时间线、设置页 UI、设备状态）不往后端扔。

### 对前端合作方的回复要点

1. **语言对齐**
   - 后端叫法：`deliverable`（交付物）= 6 docs（req/arch/tasks/api/risk/demo），不是"版本切换"的东西
   - 后端叫法：`material`（材料，待引入）= 上传的文件（PPT/PDF/图片/文档），不是 KB 文档
   - 前端"解释材料" = chat 回答，不是独立实体
   - 前端"客户问题" = 没有这个实体，从 transcript 提取

2. **后端已完成可对接的接口**
   - `GET /api/meetings` — 会议列表
   - `GET /api/meetings/{id}` — 会议聚合（FastAPI 路由）
   - `POST /api/meetings/{id}/upload_audio` — 上传音频
   - `POST /api/meetings/{id}/stream_chunk` — 30s 切片
   - `GET /api/meetings/{id}/events` — SSE 实时流
   - `GET /api/meetings/{id}/docs` — 6 文档列表
   - `GET /api/meetings/{id}/docs/{kind}` — 单个文档
   - `POST /api/meetings/{id}/chat` — chat（含 multipart 附件）
   - `POST /api/kb/search` — 知识库搜索
   - `POST /api/kb/upload` — 知识库上传

3. **前端不应后端化的状态**
   - 时间线（SSE 实时流已够用）
   - 画笔/批注/缩放等本地 UI 状态
   - 设置页 AI 配置
   - 设备状态
   - 导出 PDF（用 html2pdf.js 等前端方案）

上传处理三路：

| 文件类型 | Hermes 处理 | KB 入库 |
| .txt/.md/.csv/.json/.xml/.yaml/.yml | 直接读全文（<=50000 字，超出截断标注） | 原文件进 KB |
| .png/.jpg/.jpeg/.gif/.webp/.bmp | MiniMax vision 分析 → 图片描述文字 | 描述文本进 KB (vision_desc_ 前缀) |
| 其他 (.pdf/.pptx/.docx/xlsx) | "已存入知识库，请搜索 KB" | 原文件进 KB |
