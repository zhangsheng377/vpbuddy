# VPBuddy 产品说明书

## 一、产品定位

VPBuddy 是面向软件开发公司 VP / 售前负责人 / 项目负责人的 人机协同会议操作系统级 AI 助手。

它不是传统意义上的AI助手，而是运行在会议中的协同系统：

- 人类负责决策与主导

- VPBuddy负责理解、结构化、生成与演化

在腾讯会议 / 飞书 / 钉钉 / Zoom 中，VPBuddy 后台持续累积(无延迟约束),按 VP 主动调取:

- 会议理解与结构化建模

- 需求分析与追问

- 解释材料生成

- Sub-agent并行推理

- 交互Demo与交付物生成

- 企业/个人/行业知识库调用

- 软件交付资产持续累积(后台),按 VP 主动调取生成

核心定义：

会议 = 人机协同过程

VPBuddy = 会议中的AI协同执行系统

## 二、产品本质

VPBuddy不是单纯AI助手，而是三层系统融合：

1. 人机协同助手（用户体验层）

2. 会议操作系统（产品能力层）

3. 软件需求持续累积引擎(技术本质层)

## 三、系统结构

VPBuddy由五大系统组成：

1. 会议接入层（Join Meeting）

2. 会议理解与Agent系统（Runtime Layer）

3. 交付物生成层（Artifact Engine）

4. 指令控制层（Command Center）

5. 统一知识库系统（Knowledge Layer）

## 四、会议接入层

功能：会议入口与系统初始化

输入：会议链接、平台、项目名称、知识库选择

行为：

- 加入会议

- 初始化语音/屏幕/文本解析

- 启动Agent系统

- 加载知识库

- 创建会议工作台

## 五、会议理解与Agent系统

会议持续结构化为(后台,无延迟约束):

- 客户需求

- 业务目标

- 功能点

- 风险点

- 待确认问题

Sub-agent系统：

- 产品Agent

- 架构Agent

- UI Agent

- 数据Agent

- 风险Agent

特点：并行推理系统，而非单一工具调用

## 六、交付物持续累积与按需投屏系统

在会议过程中持续累积(后台),按 VP 主动调取:

- 交互Demo（核心）

- 页面结构

- 功能流程

- 数据模型

- API设计

- 权限模型

- 开发任务

- 工期与里程碑

核心机制:交付物持续累积演化(后台)+ VP 主动调取投屏(1-3min 软目标),而非一次性生成

## 七、指令控制层（Command Center）

VP与VPBuddy唯一交互入口

支持自然语言指令：

- 修改UI/功能

- 生成Demo

- 拆解任务

- 调用知识库

- 控制AI行为

本质：会议操作系统的控制台

## 八、会议时间轴（需求演化系统）

记录不是日志，而是：

需求如何被逐步构建为系统的过程

包含：

- 客户发言

- VP理解

- Agent触发

- 交付物变化

## 九、统一知识库系统（核心升级）

知识库是统一约束系统，包含三类知识：

1. 个人知识

- VP经验

- 决策逻辑

- 个人方案习惯

2. 企业知识

- PRD / MRD

- 技术规范

- UI规范

- 历史项目

- SOP与交付标准

3. 行业知识

- 行业标准方案

- 通用架构

- 竞品方案

- 最佳实践

作用：

不是查询，而是约束AI生成逻辑

影响：

- Demo结构

- UI设计

- 技术架构

- API设计

- 交付标准

## 十、核心系统闭环

会议输入（语音/屏幕/文档）

↓

后台持续累积(无延迟约束)

↓

Agent并行推理

↓

知识库约束

↓

交付物持续累积演化

↓

Command Center控制

↓

人类确认与投屏

## 十一、产品本质总结

VPBuddy不是传统AI助手。

它是：

- 人机协同会议操作系统

- 软件需求持续累积引擎

- 企业知识驱动的交付生成系统
