## 这是什么

VPBuddy = **会议结构化助理**。把任意会议(飞书/腾讯会议/钉钉/企微)的录音/转写自动变成:
- **6 份交付物**(每 30s 自动更新):需求清单 / 技术架构 / 任务拆解 / API 设计 / 风险分析 / **可演示 HTML**
- **跨会议知识库**(随时问"上次怎么决定的")
- **完整时间线**(全部累积项按时间倒序)
- **校准报告**(我们的 ASR vs 飞书妙记的差异)

## 5 分钟上手

### 1. 启动 controller(自动 30s 跑一轮)

```bash
~/.hermes/scripts/vpbuddy_controller.sh start
```

输出:
```
✅ Started (PID 12345)
   Log: /tmp/vpbuddy_controller.log
```

状态查询:
```bash
~/.hermes/scripts/vpbuddy_controller.sh status
```

停止:
```bash
~/.hermes/scripts/vpbuddy_controller.sh stop
```

### 2. 启动 UI(4 窗口 dashboard)

```bash
~/.hermes/scripts/vpbuddy_ui_server.sh start
```

浏览器打开: **http://localhost:8765/**

4 tab 切换:
- **主屏**: 嵌入 dashboard.html(6 卡片 + demo iframe),下拉切换会议
- **时间线**: 全部累积项按 created_at 倒序
- **知识库**: 搜 "SSO" / "碳排放" / 任何关键词
- **设置**: Controller 状态 + 数据统计 + 路径

### 3. 触发子 session(手动)


## 真实开会流程(完整路径)

```
录音(飞书/腾讯/钉钉/企微)
    ↓
飞书妙记自动转写(或我们 Step 2 的 ASR + pyannote)
    ↓
VPBuddy 累积进 MeetingState (NFS JSON: data/meetings/{mid}.json)
    ↓
Controller 每 30s 触发 6 个子 session
    ↓
    ├→ req    → 需求清单
    ├→ arch   → 技术架构 (mermaid)
    ├→ tasks  → 任务拆解 (T-XXX 格式)
    ├→ api    → API 设计 (OpenAPI 3.0)
    ├→ risk   → 风险分析 (概率×影响)
    └→ demo   → 可演示 HTML (iframe 嵌入 dashboard)
    ↓
知识库 (sqlite-vec 跨会议 RAG 检索)
    ↓
VP 在 UI 上: 看 6 文档 + 演示 + 跨会议搜索
```

## 设计原则(我们坚持的)

| 原则 | 内容 |
|---|---|
| **YAGNI** | 只做现在需要的,不预留"以后可能"的能力 |
| **不造轮子** | 直接复用 Hermes 的 session/tool/memory/session_search |
| **不主动发消息** | VPBuddy 输出是文件,不是消息;不实现 chat.send |
| **UI 展示 = prompt 的一部分** | V 看到 AI 也看到 |
| **知识库统一搜索** | 不分"双模式",统一 sqlite-vec |
| **Session 重启 = 同 id 自动 resume** | 每次 fresh chat,全 context 传过去 |
| **多子 session 并行** | 后台循环脚本 + hermes cron |
| **不指定具体工具名** | prompt 说"Hermes 会告诉你可用工具,自己选" |
| **不输出 JSON 让别人写** | LLM 自己 write_file |

## 关键技术决策

| 决策 | 选 | 不选 | 原因 |
|---|---|---|---|
| ASR | faster-whisper | Azure/讯飞 | 开源,本地,免费 |
| 说话人分离 | pyannote.audio 3.3.2 + ModelScope 镜像 | resemblyzer | 业界标准 SOTA |
| 嵌入模型 | paraphrase-multilingual-MiniLM-L12-v2 | OpenAI Embeddings | 中英 384 维,本地,~470MB |
| 向量 DB | sqlite-vec | Pinecone/Qdrant | 单文件,NFS 兼容,无外部依赖 |
| UI 风格 | Linear Dark | Vercel / 7 other | 用户选 |
| 平台 | 飞书优先 | 4 平台同权 | MVP 锁定 |
| LLM | MiniMax-M3 (Hermes) | Claude / GPT | 用户用 |
| 6 子 session | 并发常驻 | 串行 | 后台循环 + 独立 prompt |

## 常见问题

### Q: controller 在跑吗?

```bash
~/.hermes/scripts/vpbuddy_controller.sh status
~/.hermes/scripts/vpbuddy_ui_server.sh status
```

### Q: 怎么新增一个会议?

1. 用 `python scripts/seed_meeting.py` 创建示例,或
2. 自己写 `data/meetings/{mid}.json` (MeetingState 格式)
3. controller 30s 内自动触发 6 子 session
4. 6 doc 自动生成在 `docs/{mid}/`

### Q: 子 session 失败怎么办?

```bash
tail -50 /tmp/vpbuddy_controller.log
# 看具体哪个 doc_kind 失败,单独触发:
cd /home/zsd/vpbuddy
PYTHONPATH=src python -c "
from vpbuddy.sub_session_controller import trigger_sub_session
r = trigger_sub_session('YOUR_MEETING_ID', 'req')
print(r)
"
```

### Q: 知识库怎么重建?

```bash
cd /home/zsd/vpbuddy
PYTHONPATH=src python3 -c "
import os
os.environ['VPBUDDY_KB_DB'] = '/tmp/kb_rebuild.db'
from vpbuddy.knowledge_base import KnowledgeBase
from pathlib import Path
kb = KnowledgeBase(db_path='/tmp/kb_rebuild.db')
for doc_dir in Path('docs').iterdir():
    if doc_dir.is_dir() and doc_dir.name not in ('decisions','design','product-spec','research'):
        for kind in ['req','arch','tasks','api','risk']:
            f = doc_dir / f'{kind}.md'
            if f.exists():
                kb.add_document(doc_dir.name, kind, f.read_text())
        demo = doc_dir / 'demo' / 'demo.html'
        if demo.exists():
            kb.add_document(doc_dir.name, 'demo', demo.read_text())
print('✅ Done')
"
```

### Q: 飞书 chat.send 怎么用?

**不实现**!因为:
- VPBuddy 输出是文件(6 doc),不发消息
- 飞书会议录音是输入源,不是输出目的地
- VP 通过 UI shell 看 6 文档就够

如果未来真要"通知 VP 去看 6 文档",用 **飞书 WebSocket 接收** + **Hermes 内部发消息**(已经支持),不走 VPBuddy 自己的 chat.send。

### Q: 怎么录一段真会议跑端到端?

1. 录 30-60s 2-3 人对话 → WAV 16kHz mono
2. 跑 ASR:
   ```bash
   cd /home/zsd/vpbuddy
   PYTHONPATH=src python -c "
   from vpbuddy.engine import transcribe
   result = transcribe('samples/your_meeting.wav')
   print(result)
   "
   ```
3. 把 segments 灌进 MeetingState
4. controller 自动跑 6 子 session

## 出问题时

1. **controller 死了**: `~/.hermes/scripts/vpbuddy_controller.sh restart`
2. **NFS 卡死 stale 句柄**: `sudo umount /mnt/nfs_fn && sudo mount -a` (按你铁律,需要你执行)
3. **GitHub push 超时**: 用 `gh api -X PUT ...` 兜底(我在 memory 里记录)
4. **模型首次加载慢**: `paraphrase-multilingual-MiniLM-L12-v2` 首次 15-20s,后续 <0.1s
5. **端口冲突**: UI 默认 8765,设 `VPBUDDY_UI_PORT=9000 ./vpbuddy_ui_server.sh start`
6. **PROMPTS_DIR 错 / 加载了 /tmp 旧代码**: 重启 controller(脚本已强制 `PYTHONPATH=/home/zsd/vpbuddy/src`)
